# 开发计划

## 总览

| 阶段 | 主题 | 产出 | 预计工时 |
| --- | --- | --- | --- |
| Phase 0 | 脚手架与规范 | Monorepo、文档、Skill、CI 雏形 | 1 天 |
| Phase 1 | 共享层与协议 | 类型、Schema、坐标换算 + 测试 | 2 天 |
| Phase 2 | 服务端房间核心 | 连接、房间、快照、广播 | 3 天 |
| Phase 3 | 桌面端地图视图 | 地图加载、缩放平移、打点渲染 | 3 天 |
| Phase 4 | 实时协作打通 | 位置/标记同步、成员列表 | 3 天 |
| Phase 5 | 健壮性 | 重连、限流、错误处理、持久化 | 2 天 |
| Phase 6 | 打磨与发布 | 打包、文档、端到端测试 | 2 天 |

工时是粗略估计，以"验收标准通过"为完成条件。

---

## Phase 0：脚手架与规范

**任务**

- [x] 建立目录结构与文档骨架
- [ ] 初始化 npm workspaces 与根 `package.json`
- [ ] 建立 `tsconfig.base.json`、ESLint、Prettier
- [ ] 建立 Vitest 公共配置
- [ ] 补充 `.gitignore` 与基础 CI（typecheck + test）

**验收标准**

1. `npm install` 成功。
2. `npm run typecheck`、`npm test` 在空项目上可正常通过。
3. 文档中描述的结构与实际目录一致。

---

## Phase 1：共享层与协议

**任务**

- [x] 定义协议信封与全部消息类型的 Zod Schema
- [x] 定义领域模型类型（Room、Member、Marker、Route、PlayerState）
- [x] 实现坐标换算（世界坐标 ↔ 地图像素 ↔ 画布坐标）
- [x] 编写坐标往返与边界测试
- [x] 实现截图文件名解析器（位置 + 四元数朝向）与测试
- [x] ID 工具（ULID 与房间码）与测试

**验收标准**

1. 所有协议消息都能通过 Schema 校验用例（含非法输入被拒绝）。
2. 坐标换算在 3 个已知校准点上误差 ≤ 2 像素。
3. 世界坐标 → 像素 → 世界坐标往返误差 ≤ 0.5 米。

---

## Phase 2：服务端房间核心

**任务**

- [x] `ws` 网关：连接、心跳、超时断开
- [x] 房间创建/加入/离开，容量、口令与重复加入校验
- [x] 房间状态快照与增量广播
- [x] 频率限制（位置更新、标记创建、连接级总量）
- [x] 集成测试：伪造客户端完成完整房间流程
- [x] 可嵌入的 `createGameServer()` 工厂与薄 CLI 入口

**验收标准**

1. 两个测试客户端可互相收到位置与标记更新。
2. 超过容量、房间码错误、消息非法时返回明确错误码且不断开正常连接。
3. 断开连接后 30 秒内房间成员列表正确更新。

---

## Phase 3：桌面端地图视图

**任务**

- [x] Electron 主进程 + preload 安全桥（sandbox + contextIsolation + 白名单 IPC）
- [x] 截图目录监听（定时扫描、新增文件去重、连拍节流、解析失败忽略）
- [x] 地图图片加载与图层结构（4608px 无损 WebP + Canvas 2D）
- [x] 缩放、平移、复位；"跟随队友"留到 Phase 4（目前还没有队友数据）
- [x] 标记渲染与点击交互（打点、选中、重命名、删除）
- [x] 应用内标定流程（4 个控制点 + 截图坐标填充 + 重投影误差）
- [x] 端到端冒烟测试（Playwright 启动 Electron，断言地图真的画到画布上）

**验收标准**

1. 地图可流畅缩放平移（60 FPS 目标，1080p 下拖动无明显卡顿）。
2. 标记屏幕位置与预期世界坐标一致。
3. 渲染进程不启用 `nodeIntegration`，IPC 走白名单接口。

---

## Phase 4：实时协作打通

**任务**

- [ ] WS 客户端：连接、重连、心跳、离线队列
- [ ] 位置上报限流与节流渲染
- [ ] 标记/路线共享与冲突处理
- [ ] 成员列表、连接状态指示

**验收标准**

1. 两台客户端在同一房间内，A 的标记在 300ms 内出现在 B 的地图上。
2. 断网 10 秒后恢复，状态能自动追平。
3. 同一标记并发修改时，以服务端最后写入为准且不产生重复数据。

---

## Phase 5：健壮性与持久化

**任务**

- [ ] SQLite 落库：地图、房间历史、标记快照
- [ ] 服务端重启后的房间恢复策略（默认清空内存态，可恢复最近快照）
- [ ] 错误边界与日志（结构化日志、可开关的调试日志）
- [ ] 安全加固：消息体积上限、来源校验、TLS 部署文档

**验收标准**

1. 服务端重启后不再崩溃，客户端能自动重连并提示状态。
2. 超大或畸形消息被拒绝且服务端内存稳定。
3. 日志中不包含任何敏感信息（Token、完整 IP 可脱敏）。

## 风险清单

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 地图素材许可不明确 | 无法公开发布 | 优先使用明确许可的社区地图，并在文档记录来源 |
| 坐标校准精度不足 | 点位偏移、体验差 | 使用 4 点单应变换 + 多控制点回归校验 |
| 高频位置更新导致卡顿 | 渲染掉帧 | 客户端节流上报 + 服务端合并 + 渲染降采样 |
| 房间码被爆破 | 陌生人闯入 | 房间码加长、可设口令、可踢人 |
| 误入"作弊工具"边界 | 合规风险 | 严守 AGENTS.md 第十节红线，任何自动化能力都不做 |
